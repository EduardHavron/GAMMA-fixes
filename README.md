# GAMMA fixes

Фиксы и моды для сборки S.T.A.L.K.E.R. G.A.M.M.A., не связанные с кооперативом: работают и в соло. Фиксы для кооператива
[xrRazom](https://www.moddb.com/mods/xrrazom-stalker-anomaly-co-op) — в соседнем репозитории
[xrRazom-GAMMA-fixes](https://github.com/EduardHavron/xrRazom-GAMMA-fixes); устроены оба одинаково, ставятся рядом
(свои секции MO2 «GAMMA Sync» и «xrRazom Sync», свои агенты) и не трогают моды друг друга.
Любой из игроков публикует свою секцию модов сюда, GitHub Actions прогоняет тесты и собирает релиз, у остальных фоновый агент
сам ставит новую версию.

## Как это устроено

```
MO2, секция "GAMMA Sync" ──host/publish.bat──▶ main (mods/, pack/pack.json)
  (хост или друг)                                    │ GitHub Actions: тесты → проверка Lua → сборка
                                                     ▼
                                       Release vГГГГ.ММ.ДД-N (GAMMA_fixes.zip) + уведомление в Discord
                                                     │ агент, каждые 10 минут
                     ┌───────────────────────────────┴───────────────────────────────┐
                     ▼                                                               ▼
   пир без клона: скачивает релиз                                хост с клоном: publish.ps1 -SyncOnly
   → installer/install.ps1                                       (git, догон чужих изменений)
                     └────────────── MO2, только секция "GAMMA Sync" ──────────────┘
```

- В пакет идут **только включённые моды из секции-разделителя** «GAMMA Sync».
- У получателя установщик пересобирает **только эту секцию**. Чужие и тестовые моды не выключаются: если такой мод
  оказался внутри секции, он сохраняет своё состояние и переносится сразу под разделитель. Наши старые моды, которых больше
  нет в пакете, выключаются.
- Файлы хранятся побайтно (`.gitattributes`: `* -text`): в коопе xrRazom при входе сверяет моды хоста и пира, и любое
  расхождение в байтах не пустит в игру.
- `N` в версии — сквозной номер запуска GitHub Actions, а не счётчик за день.

## Публикация (хост или друг)

1. Один раз в MO2: правый клик → *Create Separator* → `GAMMA Sync`, перетащить в него моды для синхронизации.
2. После любых изменений: `host\publish.bat` из клона репозитория. Нужен git; `gh` — по желанию (ссылка на сборку и слежение за ней).

Что делает публикация:
- сравнивает каждый мод в трёх версиях: у вас в MO2, при последней синхронизации и на GitHub;
- **сначала догоняет**: чужие изменения с GitHub ставятся в ваш MO2 (MO2 нужно закрыть), ваши неопубликованные правки сохраняются;
- **публикует только ваши изменения**, нетронутые моды не перезаписывает — откатить чужую правку нельзя;
- **конфликт** (один мод изменили оба) — останавливается, ничего не отправляет и подсказывает, как решить:
  `publish.bat -TakeRemote "<мод>"` (взять версию с GitHub) или `publish.bat -TakeLocal "<мод>"` (оставить свою), `*` — для всех;
- **новый мод** в секции публикует только после подтверждения (`y`), без вопросов — с `-Yes`;
- **документацию из клона** (`specs/`, `tests/`, `tools/`, `README.md`, `CLAUDE.md`, `.claude/skills/`) публикует отдельным
  коммитом, если `tools/spec_check.py` не нашёл ошибок; иначе показывает ошибки, а моды всё равно публикует.
  `host/`, `installer/`, `agent/`, `.github/` — только вручную.

Через пару минут в [Releases](https://github.com/EduardHavron/GAMMA-fixes/releases) появляется версия.
Если тесты или проверка Lua упали, релиза не будет; ошибка видна в [Actions](https://github.com/EduardHavron/GAMMA-fixes/actions)
и приходит в Discord. Пушить могут владелец и соавторы репозитория.

## Агент автообновления

Один раз запустить `agent\setup_agent.bat` (из скачанного репозитория или из клона). Дальше раз в 10 минут, когда Mod Organizer
и игра закрыты:
- **без клона** — скачивает последний релиз и ставит его;
- **с клоном репозитория рядом с GAMMA** (режим хоста) — запускает `publish.ps1 -SyncOnly`: подтягивает чужие изменения
  и обновления самих скриптов, при конфликте показывает уведомление.

Агент обновляет сам себя: из клона или из релиза. Подробнее — `agent\README.txt`.

Без агента: скачать `GAMMA_fixes.zip` из последнего релиза, распаковать, закрыть MO2, запустить `install.bat`.

## Состав пакета

Все моды пакета в одном формате: что делает, на чьей машине нужен, где спецификация. Ставятся у всех через секцию
«GAMMA Sync»; «Где нужен» — где мод реально работает (на остальных машинах он безвреден). «В игре» — проверен ли фикс
в игре: `подтверждено`, `частично`, `не подтверждено`, `не проводилась` или `не записана` (у старых фиксов нет записи).

| Мод | Что делает | Где нужен | В игре | Спека |
|---|---|---|---|---|
| zz Task Generation Speed Fix | генерация заданий у NPC не сканирует мир заново для каждого NPC и каждого bounty-задания — «Обновить» в Taskboard и диалоги дешевле (в коопе — для хоста); в лог пишется профиль генерации | хост | не проводилась | [FX-TGEN](specs/fixes/fx-tgen.md) |
| zz Workshop Ammo Material Fix | верстак списывает все коробки-материалы | кто крафтит | не записана | [FX-WSAMMO](specs/fixes/fx-wsammo.md) |
| Combined GAMMA NPC Loot Claim v.1.2.1 | право на лут с настройкой в MCM: своих убитых обыскивает только игрок, чужих — NPC; убийства пира считаются убийствами игрока | хост и пир | не проводилась | [MOD-LOOTCLAIM](specs/fixes/mod-lootclaim.md) |
| Quantity Craft and Transfer | диалог «Сколько?» (ползунок и ввод числа): крафт рецепта N раз одним запросом, перенос и передача игроку xrRazom N предметов стопки; крафт берёт худшие, перенос и передача — лучшие; хоткей с Ctrl/Shift/Alt в MCM | у каждого (передача — только в коопе) | не проводилась | [MOD-QCT](specs/fixes/mod-qct.md) |

`FX-*` — наши фиксы, `MOD-*` — сторонние, переработанные или собственные моды (не фиксы). «Хост» у FX-TGEN — машина,
где генерируются задания: в соло это сам игрок. Заметки к отдельным модам:
- **Combined GAMMA NPC Loot Claim** — устройство, настройки MCM и план проверки от автора — в спеке [MOD-LOOTCLAIM](specs/fixes/mod-lootclaim.md). Скрипты базового NPC Loot Claim
  (`npc_loot_claim.script`, `zz_npc_loot_claim_softcore.script`) должны оставаться пустыми заглушками.

## Для разработки

Правила и чек-лист «что обновить при изменении» — [CLAUDE.md](CLAUDE.md). Сверка спек, тестов и документации —
`python tools/spec_check.py` (в Claude Code — навык `/spec-check`).

- `specs/` — спецификации (SDD): как работают публикация, CI, установщик, агент и каждый фикс. Сначала меняется спека,
  потом код и тесты. Правила и реестр ID — `specs/README.md`.
- `tests/` — автотесты по требованиям спецификаций; запускаются в GitHub Actions на каждый push, без зелёных тестов релиза нет.
  Как запустить локально — `tests/README.md`.
